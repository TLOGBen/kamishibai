# 雙模式決策：一次性著作文件 vs 可重繪資料視圖

Status: resolved
Type: grilling
Blocked by: 02, 07

## Question

SDK 的客戶分兩種本質不同的產出：（a）模型一次性「著作」的定稿文件（book、錯字修改表、工作日誌），與（b）資料驅動、每次狀態變更就重繪的視圖（wayfinder 地圖、strategic-advance 沙盤——帶 --language 等確定性參數）。SDK 要以單一抽象同時吃下兩種，還是明確分成兩個模式／兩組 API？哪一種是第一公民？

## Answer

選 **A：單一管線「一切皆內容＋模板」**。模型不再著作 HTML，而是著作結構化內容 IR（帶 schema 的區塊樹）；渲染一律由 SDK 確定性完成。為保住 book 級表現力，IR 保留「raw 島嶼」逃生艙——模型可在特定槽位嵌入自寫 HTML/SVG 區塊，且島嶼佔比可被品質閘門量測。紅利：著作文件與資料視圖同樣可重繪，主題改版時歷史產物可一鍵換皮；品質閘門可統一驗 IR。已接受的邊界：所有既有 skill 都需改產 IR，遷移工程量最重（由 08 遷移票承擔）。

追加需求（使用者於結案時提出）：承接 book「把輸出帶去任何地方、像真實書本」的原始意象，**SDK 產物必須能單獨生存**——自包含、離線可開、不依賴 SDK 存在。產物規格獨立成票：[產物規格：單獨生存的輸出物](10-artifact-spec.md)。

## Comments

- 2026-08-16 使用者定調：wayfinder 與 strategic-advance 的視圖未來「都是用同一風格模板的產物，透過 SDK 來做呈現」——即資料視圖模式確定在範圍內，且與著作文件共用同一模板／主題家族。本票剩下的核心是 API 怎麼切，而非要不要支援。
