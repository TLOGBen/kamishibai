# 產物規格：單獨生存的輸出物

Status: resolved
Type: grilling

## Question

承接 book 的原始意象——「把輸出帶去任何地方，就像真實書本一樣」——kamishibai 的產物必須能離開 SDK 單獨生存。這張票定產物的規格：

1. **自包含程度**：CSS/JS 內聯是底線；字體（如 TsangerJinKai02）要不要內嵌（膨脹 vs 離線忠實度）？圖片一律 data URI？
2. **IR 隨行**：既然核心抽象是「內容 IR＋模板」（05 定案），產物要不要內嵌自己的 IR——一份 HTML 自帶原稿，未來任何時點都能被 SDK 重新換皮／升級？嵌在哪（`<script type="application/...">`？sidecar 檔？）、算不算規格必要項？
3. **格式家族**：HTML 之外，PDF／PPTX（book 現有）是產物一等公民還是匯出附屬？
4. **尺寸與相容底線**：單檔上限、離線無網路、無外部資源請求（現有各 renderer 已遵守）、瀏覽器相容範圍。

## Answer

四題定案（2026-08-16 使用者確認）：

1. **字體：build 時子集化**——渲染時掃描產物實際用字、只嵌用到的字形（中文長文約數百 KB），缺字退系統字型堆疊。
2. **IR 隨產物內嵌，為規格必要項**——canonical block tree＋模板 id＋版本以 `<script type="application/json">` 藏進 HTML。每份產物自帶原稿，任何時點可被 SDK 重新換皮／升級／轉格式，不依賴原始檔案存續。
3. **HTML 是唯一一等公民；PDF／PPTX 為匯出附屬**（由轉換器自 HTML 派生，不承諾 IR 隨行）。**追加（使用者指定）：HTML 產物須內建「播放能力」**——演講／簡報模式（全螢幕、鍵盤翻頁等）直接活在單檔產物內，簡報的本體是 HTML 而非 PPTX 原稿。
4. **尺寸與相容**：單檔軟上限 10MB（CLI 警告並列出肥胖來源）、硬上限 16MB，**兩者皆可設定覆寫**（避免真實個案被上限卡死）；零外部請求（CSP meta 自我驗證）；相容目標 evergreen 瀏覽器。

播放模式的細部（鍵盤配置、講者備註等互動元件詞彙）併入 11 號票。
